# Plan de acción PEC 2

**Entrega del aula:** 03/11/2026. **No se presupone que las tareas estén completadas.**

## Tarea 2.1 — Estado del arte ampliado (07/10–18/10; 20 h)
- [ ] Buscar y descargar fuentes originales; registrar buscador, consulta, fecha y criterios.
- [ ] Verificar las referencias de la PEC1 y corregir cifras erróneas.
- [ ] Completar la matriz comparativa de estudios y explicar el gap.
- [ ] Separar trabajos revisados por pares de preprints y publicaciones de proveedores.

## Tarea 2.2 — Benchmark y taxonomía (14/10–21/10; 15 h)
- [ ] Elegir 10 contratos mínimos; objetivo 12, máximo 15.
- [ ] Distribuirlos entre cinco categorías, dos o tres por categoría.
- [ ] Guardar contratos originales, licencias y enlaces de origen.
- [ ] Verificar localización vulnerable, versión solc y hash SHA-256.
- [ ] Crear versiones sin comentarios reveladores; conservar el original.
- [ ] Identificar 1-2 controles negativos si son verificables.

## Tarea 2.3 — Protocolo experimental (19/10–26/10; 20 h)
- [ ] Revisar el protocolo V4 con el tutor y congelarlo antes de iniciar la campaña experimental.
- [ ] Definir unidad de hallazgo y reglas TP/FP/FN, duplicados y pendientes.
- [ ] Acordar rúbrica cualitativa y qué significa un parche válido.
- [ ] Registrar el modelo exacto, configuración de razonamiento, fecha, prompt y respuesta íntegra de ChatGPT, Gemini y Claude en modo conversacional.
- [ ] Definir repeticiones y subestudio opcional de variantes de modelo.

## Tarea 2.4 — Preparación de herramientas (22/10–29/10; 18 h)
- [ ] Preparar Linux/WSL/Docker y anotar versiones de Python, solc, Slither y Mythril.
- [ ] Confirmar accesos a ChatGPT, Gemini y Claude, sin compartir credenciales.
- [ ] Preparar el repositorio de GitHub con este esqueleto.
- [ ] Verificar compilación de dos contratos antes de hacer auditorías.

## Tarea 2.5 — Prueba piloto (29/10–03/11; 12 h)
- [ ] Elegir un caso de reentrancia y otro de control de acceso.
- [ ] Ejecutar los analizadores tradicionales y conservar logs.
- [ ] Ejecutar una auditoría con cada plataforma y guardar respuesta íntegra.
- [ ] Aplicar adjudicación y rúbrica; documentar ambigüedades.
- [ ] Ajustar el protocolo si es necesario y repetir el piloto afectado.
- [ ] Incorporar al Word **solo evidencias realmente obtenidas**.

## Entregables a conservar
- Matriz bibliográfica y búsqueda reproducible.
- Tabla de contratos y etiquetas.
- Protocolo y prompt versionado.
- Registro de versiones del entorno.
- Dos casos piloto con evidencias, o incidencias técnicas documentadas.
- URL real del repositorio GitHub (no usar un enlace de ejemplo en la memoria).
